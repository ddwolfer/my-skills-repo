dual-plan
One plan, two artifacts.

寫實作計畫的時候同時產出 plan.md(給 AI 執行用)和 plan.html(給人類討論用)。MD 是正本,HTML 是 view,單向 render,不會同步出問題。

SKILL · dual-plan v1.1 TRIGGER · /dual-plan SCOPE · user-level DEPS · python 3.13+ · marked + mermaid (CDN)
I

概念The Concept · Why Two Files

Markdown 對 AI 友善(token 便宜、易 diff、易 stream),HTML 對人類友善(視覺豐富、可分享、易讀)。這個 skill 不會同時維護兩份檔(那會 drift),而是把它們當成同一份內容的兩個 render target。

II

什麼時候該用When to Fire · When to Skip

適用

Fire

  • 使用者打 /dual-plan
  • 多步驟 feature 設計、架構決策
  • 需要拍板的取捨與方向
  • 「幫我規劃 / plan / 設計 X」
  • plan mode + 任務 ≥ 30 分鐘
不適用

Skip

  • 單行 bug fix、改變數名
  • 純探索 / 純問答
  • 已有 plan,只是要執行
  • auto mode 下的 routine 任務
  • 使用者要的是「直接做」
III

怎麼用How to Use · 3 Steps

觸發 skill

對 Claude Code 打 /dual-plan 加上你想規劃的事。例如「/dual-plan 加一個使用者通知偏好的設定頁」。或者只是說「幫我規劃 X」也會觸發。

在 HTML 上看計畫、給回饋

Claude 會把計畫寫成 plans/<date>-<slug>/plan.md,並 render 成 plan.html。打開 HTML 在瀏覽器看(雙擊即可),有意見就回到 Claude Code 講。Claude 會改 MD 並重新 render。

說「好,開始做」

計畫定稿後說「approve / 好 / go / 開始做」,Claude 就會根據 plan.md 執行。從這一步開始 plan 凍結;若要改請先停下,重新進入討論模式。

IV

檔案結構What Gets Generated · Where

每個 plan 自成一個資料夾,放在當前 working directory 的 plans/ 底下。plan.html 預設會被加入 .gitignore(diff 噪音太大,而且 HTML 隨時可從 MD 重 render)。history/ 由 render script 自動維護,版本 bump 時自動 snapshot 舊版。

<cwd>/ ├── plans/ │ ├── 2026-05-10-feature-x/ │ │ ├── plan.md ← AI 讀這份(canonical · 含 YAML frontmatter) │ │ ├── plan.html ← 人讀這份(由 render.py 產出,gitignored) │ │ ├── history/ ← 自動 snapshot,版本 bump 時保存舊版 │ │ │ ├── v0.1.md │ │ │ └── v0.2.md │ │ └── attachments/ ← 截圖、reference(可選) │ └── 2026-05-12-other-thing/ │ └── ... └── .gitignore ← skill 自動加入: plans/**/plan.html
V

技術架構How It Works Under the Hood

Skill 安裝在 user-level:

~/.claude/skills/dual-plan/ ├── SKILL.md ← skill 主體(Claude 讀這份決定怎麼做) ├── render.py ← MD → HTML render script(stdlib only) ├── README.html ← 你正在看這份 └── templates/ ├── plan-render.html ← render template(每份 plan.html 的母版) └── plan.md.skel ← 新 plan 起手式 skeleton(含 frontmatter)

Render 流程:Claude 執行 python ~/.claude/skills/dual-plan/render.py path/to/plan.md,script 自動處理:讀 frontmatter → 取 title/version/slug → 讀 template → 替換 title / masthead / timestamp / 內嵌 MD → 寫 plan.html。瀏覽器打開後,內建的 marked + mermaid CDN 會把 markdown render 成你看到的版本。

自動版本 snapshot:render.py 會檢查舊 plan.html,若內嵌的 MD 版本與 frontmatter 新版本不同,自動把舊版 MD 抽出來存到 history/v<old>.md。完全自動,無須手動備份。

無 toolchain:render.py 只用 Python stdlib,template 用 CDN 載 marked + mermaid。沒有 build step、沒有 server。雙擊 HTML 在 file:// 協定下就能跑。

內建 bug 修正:template 包含一個 markdown pre-processor,會偵測 raw HTML block 內的空白行並用 <!----> 取代,避免 marked 把 SVG 內容當成新的 markdown 解析。

VI

自訂Customization

三個常見的調整方向:

改視覺風格:編輯 templates/plan-render.html 開頭的 :root { --bg, --ink, --accent ... } CSS 變數。改字型則調整 <link> 的 Google Fonts URL 跟 font-family。

改觸發行為:編輯 SKILL.md 開頭的 description frontmatter。Claude 用這段判斷什麼時候自動建議使用這個 skill,寫得越具體觸發越精準。

新增豐富互動:在 plan.md 內可直接寫 raw HTML(SVG 插畫、slider 控件、Copy-as-Prompt 按鈕等)。template 的 CSS 已經預備好對應的 .figure / .tuner / .slider / .export-btn 樣式可以直接用。

frontmatter 標準化:每份 plan.md 開頭有 YAML frontmatter(title / version / status / created / updated / slug),render.py 用它驅動標題、masthead、與版本 snapshot。skeleton 在 templates/plan.md.skel。

注意:在 plan.md 寫 raw HTML 區塊時,內部不要放空白行。template 已經有 pre-processor 修正,但寫得緊湊比較保險。

VII

FAQ

為什麼不直接用 Markdown 就好?
超過 100 行的 markdown 多數人不會讀,自己也容易跳過。HTML 可加圖、加結構、加顏色、可分享,人類讀的比率高很多 — 而 plan 沒有人讀就等於沒寫。
為什麼不直接用 HTML 就好,連 MD 都不要?
AI 執行 plan 時讀 HTML 會多吃 2-4 倍 token,且 diff 對 review 不友善。MD 是 canonical,HTML 是 view,各司其職。
改了 HTML 之後 MD 會不會被反向更新?
不會,而且不該會。改請改 MD,讓 Claude 改完之後重新 render HTML。HTML 是「render 的結果」,不是 source。
為什麼 HTML 要 gitignore?
HTML 的 diff 噪音太大,review 時根本沒人看;且 HTML 隨時可從 MD 重 render,沒有保留必要。MD 進 git,留歷史紀錄即可。
需要安裝什麼?
不用。template 用 CDN 載 marked 和 mermaid,雙擊 HTML 就跑。前提是電腦能上網。
能離線用嗎?
目前不行(CDN 依賴)。如果有需求可以把 marked 和 mermaid 下載到本地,改 template 引用 local 檔。但常見情境(寫 plan 通常有網)目前夠用。
執行中 plan 改了會怎樣?
不處理。skill 文件有寫:execute 階段 plan 凍結,要改請停下重新討論。如果你在 AI 執行到一半時改了 plan.md,當下執行不會中斷;下一輪 AI 才會看到新版。
能不能改成全自動,不需要 approve?
可以,但不建議 — 這個 skill 的核心價值就是「人類能在執行前看清楚計畫」。如果你要全自動,根本不需要 dual-plan,直接讓 AI 執行就好。
history/ 裡的舊版本要不要進 git?
建議進 git。plan.html 因為 diff 太吵被 gitignore,但 plan.md 與 history/v*.md 都是 canonical 文字,進 git 留歷史是合理的(且比 git tag/branch 輕量)。
render.py 需要安裝什麼套件嗎?
不用。只用 Python 3 stdlib(re、pathlib、datetime、html)。Python 3.13+ 測過。frontmatter parser 是手寫的小型 YAML 子集,不依賴 PyYAML。
如果 Python 不能跑怎麼辦?
Claude 可以手刻 HTML(讀 template、做 4 個替換、寫 plan.html)當 fallback,但會多吃 ~19 KB context per render,且失去自動 snapshot。優先用 render.py。

v1.1 — 2026-05-10 · dogfooding 後優化
第一次實際用 dual-plan 規劃(v0.1 → v0.3 三輪 iterate)後發現的痛點修復。主要改動:
  • 新增 render.py —— 取代 Claude 手刻 HTML,每次 render 省 ~19 KB context、自動處理 timestamp / title / masthead 替換
  • 新增 YAML frontmatter 必填規範(title / version / status / created / updated / slug)
  • 新增自動版本 snapshot 機制 —— render.py 從舊 plan.html 抽 MD 存到 history/v<old>.md,完全無感
  • 新增 templates/plan.md.skel —— 含 frontmatter 的 plan 起手式
  • SKILL.md re-render policy 改成「edit batch 結束才 render」(避免 spam render)
  • 修 Windows console cp950 編碼讓 · 與 CJK 不亂碼
v1.0 — 2026-05-10 · initial release
Skill 從零打造。核心結構:SKILL.md + templates/plan-render.html 母版 + README。MD 是 source of truth,HTML 是 view。Render 由 Claude 手刻(後來在 v1.1 改成 script)。
  • 受 Thariq《Using Claude Code: The Unreasonable Effectiveness of HTML》啟發
  • 單檔 HTML + CDN 載 marked + mermaid,無 toolchain
  • 內建 marked tokenizer fix(raw HTML 區塊空白行 bug)
  • 自動 gitignore 處理(首次 render 時加入 plans/**/plan.html)
